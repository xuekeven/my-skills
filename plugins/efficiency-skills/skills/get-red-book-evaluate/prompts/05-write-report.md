# 05 - 写 Markdown 报告

## 目标

把采集结果写成结构稳定、可读、可追溯的 Markdown 文件。

## 输入

- 有效用户帖列表
- 辅助材料列表
- 跳过帖子列表及原因
- 正文摘要
- 评论分类要点
- 页面限制说明
- 采集日志
- 采集状态、来源角色和单帖证据质量
- 输出路径

## 动作

先按主模式选择且只读取一份报告模板：

- `商品`：`templates/report-product.md`
- `品类`：`templates/report-category.md`
- `事件`：`templates/report-event.md`
- `实体`：`templates/report-entity.md`

主模式不明确时返回 `01-clarify.md`，不得自行混用模板。选定模板后，按模板结构写入有效用户帖和辅助材料，并保留证据来源和原始 URL：

1. 帖子标题和 URL 写在同一个 Markdown 超链接标题中，例如 `### 1. [帖子标题](帖子完整URL)`
2. 时间
3. IP 地址
4. 按模板使用独立正文/评论表格，或使用带“来源”列的合并证据表格
5. 每条证据至少包含用户名、短证据片段、信息类型、总结要点和立场/评价；合并表格还要标明来自正文还是评论
6. 该帖子的模式相关信号
7. 已查看评论数量
8. 采集状态、来源角色和单帖证据质量

报告末尾补充：

- 目标有效帖数量、实际有效用户帖数量、候选帖数量、实时打开贴峰值、最多查看贴数量（累计）和辅助材料数量
- 采集状态和单帖证据质量
- 跳过帖子数量与原因，例如广告、时间不符、IP 不符、信息缺失
- 停止采集原因：已达到目标有效帖，或最多查看贴累计达到 30 个后有效用户帖仍不足；后一种情况必须说明不足目标数量的原因
- 采集限制，例如折叠评论/回复、加载失败
- 标签页批处理说明：每篇记录完成后默认关闭已处理标签页，但有效用户帖和辅助材料原始 URL 已保留，可按 URL 回看
- 每个已评估帖子打开后至少等待 3 秒、页面加载/评论扫描超时、重试和部分完成状态
- 结论主要由多少个独立帖子印证，还是仅由单帖/单条评论支持
- 跨帖结论置信度及判定依据
- 无价值帖、广告帖、时间/IP不符帖的跳过统计

## 写作要求

- 用中文。
- 简短清晰。
- 不要大段照抄原文。
- 只保留短摘录或证据片段，不复制长段正文或评论。
- 商品模板分别展示正文表格和评论表格；其他模式可按模板使用带“来源”列的合并证据表格。
- 证据表格不得省略用户名、证据片段、信息类型、总结要点和立场/评价；合并表格不得省略“来源”列。
- 表格中的“用户名”填写正文作者或评论作者；无法稳定识别时写“未识别”，不要猜。
- 标明哪些结论只是单条评论观点。
- 每篇有效用户帖和辅助材料必须保留 URL，并且标题和 URL 必须合并为超链接形式，不再单独写 `URL：...`。
- URL 使用从页面获得的原始链接，不手动改写、清洗或短链化。
- 如果中途因批次标签页管理关闭过帖子标签页，报告仍必须使用关闭前记录的原始 URL。
- 报告顶部采集元信息使用两列表格展示，列名为“项目”和“内容”。
- 报告顶部写明主题边界、排除项和实际使用过的每组搜索词。
- 保留所选模板的模式专属章节，不把其他模式的章节强行加入报告。
- 每篇有效用户帖的元信息使用两列表格展示，列名为“项目”和“内容”，包含：时间、IP、来源角色/利益关系、是否疑似广告、已查看评论数量、采集状态、单帖证据质量、模式相关标签、有效性判断。
- 当事人、官方或利益相关方材料放入单独的“辅助材料”章节，不与普通用户评价混排，也不计入目标有效帖数量。
- 不使用旧的复合时间字段名，统一写成“时间”。
- 不要把“打开过的帖子数”写成“有效帖数”。
- 已查看评论数量按“主评论 + 展开回复逐条计数”填写。

## 产出

- Markdown 报告草稿
- 实际使用的模板路径

## 完成标准

- 每篇有效用户帖都有独立章节，辅助材料单独成节。
- 报告结构与主模式对应，且只使用了一份模式模板。
- 每篇标题都是可点击的 Markdown 超链接，链接为唯一 URL，方便用户回看。
- 每篇都有时间和 IP。
- 每篇有效用户帖都有已查看评论数量；辅助材料也记录实际查看数量。
- 每篇都有采集状态和单帖证据质量；部分完成的帖子明确写出缺失信息和影响。
- 报告没有把单条评论包装成确定事实。
- 报告只把小红书页面展示的信息称为“页面可见信息”；未经外部核验的现实事件信息不写成已证实事实。
- 报告明确声明样本只代表本次小红书可见结果，不代表平台整体用户、公众民意或事实核查结论。
