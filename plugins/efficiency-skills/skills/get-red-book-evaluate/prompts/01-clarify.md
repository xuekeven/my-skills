# 01 - 澄清输入

## 目标

只澄清执行任务所必需的信息，并从用户请求中提取筛选条件。

## 输入

- 用户原始请求

## 动作

1、提取

从用户请求的描述中：
- 提取主题名称和主模式：商品、事件、实体或品类。
- 提取主题边界与消歧信息，例如事件日期/地点/相关主体、实体全名/行业/身份、品类包含与排除的子类。
- 提取评价目的，例如购买决策、舆情综述、口碑调查、争议梳理、适用性或趋势判断。
- 提取原始搜索关键词；按 `references/topic-modes.md` 生成少量扩展词。
- 提取用户特别关注的评价维度。
- 提取是否指定目标有效帖数量。
- 提取是否指定时间范围。
- 提取是否指定 IP 范围。
- 提取是否指定输出路径。
- 如果用户指定目标有效帖数量，将其规范到 5-20 篇范围内：少于 5 按 5，多于 20 按 20。

2、确认

如果主题名称/边界、主模式、评价目的、数量、时间/IP范围或输出路径存在实质歧义，向用户确认。主题名称不可为空；存在同名事件、同名实体或品类范围歧义时必须先消歧。请求已经明确且没有冲突时，可复述解析结果和默认值后直接进入下一步。

- 主题名称不为空但存在实质歧义时，使用模版1提问。如果用户回复“确认”之类的认可语句，进入下一步；否则，综合用户所有回复，回到“1、提取”。
- 主题名称为空时，使用模版2提问。针对用户的回复，回到“1、提取”。

模版1：

```
收到，总结如下：

**主题**：${主题名称}
**主模式**：${商品/事件/实体/品类}
**主题边界/排除项**：${日期地点、实体身份、品类范围或“无”}
**评价目的**：${评价目的}
**搜索关键词**：${原始关键词和扩展词}
**关注维度**：${关注维度}
**目标有效帖数量**：${目标有效帖数量}
**时间范围**：${时间范围}
**IP 范围**：${IP 范围}
**总结输出路径**：${总结输出路径}

确认吗，可以的话，我直接开始下一步。
```

模版2：

```
针对您刚刚的输入，我未能提取到评价主题这个关键信息，请您直接复制以下内容，填写后发给我。

**主题名称（必填）**：
**主题类型（商品/事件/实体/品类）**：
**主题边界/排除项**：
**希望了解什么**：
**关注维度**：
**目标有效帖数量**：
**时间范围**：
**IP 范围**：
**总结输出路径**：

```

## 默认值

- 目标有效帖数量默认 8 个；用户可指定 5-20 个，实际按有效用户帖计数。
- 主模式能从请求可靠判断时直接采用；无法判断时询问用户。
- 评价目的未指定时，商品默认购买决策，事件默认讨论焦点与待核实事项，实体默认口碑与争议，品类默认适用性、差异与趋势。
- 关注维度未指定时按 `references/topic-modes.md` 选取与主模式有关的维度，不强行覆盖所有维度。
- 如果用户指定少于 5 个，目标有效帖数量按 5 个执行，并在确认里说明“已按最少 5 篇处理”。
- 如果用户指定多于 20 个，目标有效帖数量按 20 个执行，并在确认里说明“已按最多 20 篇处理”。
- 如果用户不指定时间范围，不按时间过滤。
- 如果用户不指定 IP 范围，不按 IP 过滤。
- 如果用户不指定输出路径，默认写到工作区文件。

## 产出

- 主题名称和主模式
- 主题边界与消歧信息
- 评价目的和关注维度
- 原始搜索关键词与扩展词
- 目标有效帖数量
- 时间范围过滤条件，可能为空
- IP 范围过滤条件，可能为空
- 输出路径

## 完成标准

- 已具备主题名称、主模式、评价目的和搜索词，可开始打开小红书并搜索。

## 注意事项

- 不要追问过多格式细节。
- 用户目标明确时不必为了形式再追问一轮；应在开始前复述实际采用的默认值。
