# 00 - 总体目标

## 目标

把小红书搜索结果整理成一份可追溯、能回答用户评价目的的 Markdown 报告。

## 输入

- 主题名称和主模式：商品、事件、实体或品类
- 用户希望回答的评价目的
- 搜索关键词及必要的扩展词
- 目标有效帖数量，默认 8 个，允许范围 5-20 个；实际按有效用户帖计数
- 可选时间范围，例如“近一个月”“2026-03-01 到 2026-06-01”
- 可选 IP 范围，例如“只看北京/上海 IP”
- 输出路径，默认工作区 Markdown 文件

## 帖子数量口径

- **目标有效帖**：本次任务需要采集的有效用户帖总数，默认 8 篇，范围 5-20 篇；少于 5 按 5，多于 20 按 20，并在参数确认中说明。
- **实时打开贴**：任一时刻同时打开的帖子数，最多 10 篇，无最小值。
- **最多查看贴**：全程首次打开并开始查看的帖子累计数，最多 30 篇，无最小值；有效、辅助、跳过和打开后受阻的帖子都计入，同一 URL 回看重开不重复计数。

## 动作

- 使用 `chrome:control-chrome` 选择 Edge 浏览器绑定并接管 Microsoft Edge。
- 新页签打开 `https://www.xiaohongshu.com/` 并完成前置检查。
- 按 `references/topic-modes.md` 识别主模式、关注维度和结论形式。
- 使用用户原始关键词和少量模式相关扩展词搜索。
- 按视觉顺序收集候选卡片并去重，分批交给评估步骤；候选帖数量、实时打开贴数量、最多查看贴数量、有效用户帖数量和辅助材料数量分别记录。
- 搜索步骤不打开帖子；评估步骤对每个候选帖只用一个新标签页打开一次。
- 达到目标有效帖后立即停止收集和打开新候选帖。
- 实时打开贴最多 10 篇；单批最多处理 10 篇候选帖，每篇记录完成后默认关闭其标签页，保留原始 URL，避免标签页过多导致电脑卡顿。
- 最多查看贴是累计打开并查看过的帖子数，最多 30 篇；达到 30 篇仍未达到目标时停止打开新候选帖。
- 每篇都先看正文，再看评论。
- 只保留和当前主题及评价目的相关的有价值信息。
- 按评价模式给出商品购买建议、品类选型分析、事件讨论综述或实体口碑分析。
- 对页面限制、采集状态、单帖证据质量和跨帖结论置信度做明确标注。

## 有效用户帖定义

有效用户帖必须同时满足：

- 与主题直接相关，并达到对应模式的最低信息要求
- 不是明显广告贴或暗广
- 如果用户指定时间范围，能看到帖子时间，帖子时间符合要求
- 如果用户指定 IP 范围，能看到帖子 IP 地址，帖子 IP 符合要求

## 产出

- 一份 Markdown 报告。
- 每篇有效用户帖单独成节；辅助材料单独成节。
- 每篇都写明标题、URL、时间、IP、来源角色、正文要点、评论要点。
- 记录证据类型、立场/评价和是否待核实。
- 结尾包含跨帖子综合结论。

## 完成标准

- 报告直接回答用户的评价目的；商品回答是否值得买，事件回答讨论焦点和待核实点，实体回答口碑与争议，品类回答共性、差异和适用场景。
- 报告中明确说明查看了多少个有效用户帖和辅助材料，以及跳过了哪些类型的帖子。
- 报告中明确说明目标有效帖数量、实际有效用户帖数量、候选帖数量、实时打开贴峰值、最多查看贴数量和辅助材料数量，以及停止原因。
- 如果最多查看贴达到 30 篇仍未达到目标，说明不足目标数量的原因。
- 报告中明确说明是否按批次关闭过已处理帖子标签页，并保留每篇有效用户帖和辅助材料的原始 URL 方便回看。
- 报告中明确说明哪些帖子为 `完整` 或 `部分完成`，并说明单帖证据质量、跨帖结论置信度及页面限制。
