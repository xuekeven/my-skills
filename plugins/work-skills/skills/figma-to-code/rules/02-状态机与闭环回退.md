## S1 身份与状态

### S1.1 固定身份

首次确认后固定：`run_id`、`input_type`、`figma_file_key`、`frame_id`、`frame_name`、`frame_width`、`frame_height`；截图输入再固定原图哈希。

Frame 名称变化先复核并记录。文件 key、Frame ID、宽度、高度或截图基准哈希变化时，视为设计身份变化，下游全部失效，回第一阶段。

### S1.2 状态集合

- `stage_1_planned`：读取和计划已形成，字段/资产门禁未完成。
- `stage_2_assets_ready`：关键字段达标，正式资产全部 QA 通过。
- `stage_3_implemented`：独立页面已实现，适用代码与运行检查通过。
- `stage_4_validating`：正在截图、diff、audit、评分和局部修正。
- `complete`：第四阶段全部停止条件通过。
- `blocked`：关键来源、能力或用户决策不可得，安全替代路径已耗尽。

每次转换记录来源、目标、原因、时间、阶段/子阶段耗时、触发证据、失效产物和恢复路径。

## S2 前进门禁

1. 第一 → 第二：身份和最终视觉确认；完整图层/区域读取；分类、风险、补读队列和切图计划可审计。
2. 第二 → 第三：读取完整度符合 P7/A2；无关键 blocking；用户资产边界落实；必需资产机器与视觉 QA 全通过。
3. 第三 → 第四：独立页面/路由可访问；默认态、捕获根和尺寸明确；manifest 引用一致；适用 lint/类型/测试/构建/运行检查通过。
4. 第四 → 完成：截图前置、整体/section diff、10 类 audit、多维阈值、综合还原度、回归和资产一致性全部通过。

不得通过降低阈值、隐藏问题、整页截图、伪造报告或跳过检查绕过门禁。

## S3 根因回退表

| 发现/根因 | 回退位置 | 最小动作 |
|---|---|---|
| 文件、Frame ID、尺寸或截图基准变化 | 第一阶段 | 废弃下游身份相关产物，重新读取和规划 |
| section、图层、bbox、文本 run/折行、渐变、蒙版、层级、组件 override 等缺失/错误 | 第二阶段补读 | 只补读最小节点/子树，更新来源、置信度及依赖计划 |
| PNG/SVG 分组、内容、来源、格式、倍率、透明、边界、比例、方向或哈希错误 | 第二阶段资产 | 只重导受影响资产并完成全部 QA |
| 实现暴露资产遗漏或字段错误 | 第二阶段 | 记录暴露位置，修上游后顺序恢复第三、四阶段 |
| 布局、文字、CSS、组件、路由、层级或默认交互实现错误 | 第三阶段 | 只修受影响区域/组件，再进入第四阶段 |
| 截图尺寸、倍率、裁切、空白、加载或左上角对齐错误 | 第四阶段前置 | 只修捕获配置；通过前不产生 diff 结论 |
| 本轮局部修正破坏已通过区域 | 当前修正轮 | 撤销当前执行者本轮修改，确认基线恢复后缩小范围 |
| 浏览器/Figma 渲染差异且证据证明不可修 | 第四阶段 | 记录不可约扣分、影响和消除条件，不伪装已修 |

局部问题不重跑整页；错误资产不靠 CSS 补；错误字段不靠最终偏移掩盖；截图错误不算页面差异。

## S4 产物失效规则

| 发生变化 | 必须失效 |
|---|---|
| Frame/基准身份 | 第一阶段分析后的全部计划、资产、实现截图、diff、audit、评分 |
| 关键结构字段或 section | 依赖该字段的分组、资产、实现、截图、diff、audit、评分 |
| 资产分组/文件/哈希 | 该资产 QA、引用它的实现截图、diff、asset audit 和评分 |
| 页面代码/CSS/默认态 | 旧预览截图、diff、受影响 audit、评分和完成判断 |
| 捕获参数 | 旧预览截图、diff 和所有像素指标；页面代码本身不自动失效 |
| 验收阈值 | 旧通过结论和评分；原图与预览图可在身份/代码未变时重新计算 |

回退后在 `invalidated_artifacts` 中明确记录。任何失效文件即使仍在磁盘，也不能作为当前证据。

## S5 阶段回退与本轮撤销

### S5.1 阶段回退

上游交接物错误或不完整时回到负责阶段，更新依赖项，再按顺序恢复后续阶段。每次恢复必须重新运行相应门禁，不能因曾经通过而跳过。

### S5.2 本轮撤销

第四阶段局部修正前记录目标文件/区域、基线截图、diff、分数和已通过 section。若产生回归，只撤销当前执行者在本轮产生的精确修改。

禁止 `git reset --hard`、`git checkout --` 或任何可能覆盖用户既有修改的广域命令。无法可靠分离本轮修改时停止并说明，不猜测回退。

## S6 循环、回归与阻塞

### S6.1 循环规则

- 同一缺失字段最多定向补读 3 轮；达到门禁、非关键风险降级或关键 blocking 后停止。
- 资产重导没有固定次数，但每轮必须改变根因策略并重新 QA；不能重复同一错误导出。
- 第四阶段在综合还原度低于 98 分且存在可修差异时继续；达到 98 分及以上即可交付并暂停继续循环，保留剩余差异、证据和后续消除条件。
- 同一指标连续 3 次针对性修改无改善时重新归因并回上游，不继续堆补丁。

### S6.2 回归

以下任一项为 `regression_error`：已通过 section 超阈值；正确折行/层级/资产被破坏；整体或关键 diff 恶化；新增运行时/构建/滚动/交互错误；为局部问题修改无关区域；综合还原度下降。

回归优先处理。撤销本轮自有修改后重新截图，确认基线恢复，再采用更小修正。

### S6.3 阻塞

只有关键来源、能力或用户决策确实不可得，且已尝试所有安全、范围内替代路径时才标 `blocked`。同时记录：阻塞字段/资产、已尝试路径、为什么不可继续、最小恢复条件和哪些产物仍有效。

## S7 状态持久化

把用户指定或从目标项目推导出的输出目录记为 `delivery_root`。应用源码和正式资产遵循目标仓库约定写入其中；工作流证据统一写入：

```text
<delivery_root>/
  <应用源码与正式资产>
  .figma-to-code/
    runs/
      <run_id>/
        stage-1-handoff.json
        stage-2-handoff.json
        stage-3-handoff.json
        stage-4-handoff.json
        asset-manifest.json
        figma-reference.png
        stage-3-preview.png
        stage-3-capture-report.json
        stage-4-preview.png
        stage-4-capture-report.json
        stage-4-visual-diff-report.json
        stage-4-diff.png
        stage-4-audits.json
        stage-4-iteration-history.json
        timing.json
        qa/
          stage-2-asset-qa.json
          stage-2-asset-contact-sheet.svg
        diagnostics/
          stage-2-asset-attempts.json
```

用 `scripts/workflow.mjs init` 初始化目录。`state.json` 不是默认产物，因为完整 `workflow_state` 已嵌入每个阶段交接；仅兼容旧消费者时生成。section 以 `stage-1-handoff.json#handoff.design_analysis.layout_structure.sections` 为唯一规范来源，不生成独立 `sections.json`。逐资产机器 QA 在临时目录执行，正式结果通过 `scripts/asset-qa.mjs bundle` 合并为一个 `qa/stage-2-asset-qa.json`。

`diagnostics/stage-2-asset-attempts.json` 仅在发生失败尝试时创建。第二阶段候选、逐资产临时 QA 和未通过文件放在 `/tmp/figma-to-code/<run_id>/stage-2-candidates/`，不进入运行目录；运行目录不保留批量逐资产预览或失败二进制。第四阶段 audit 与迭代历史仍分开保存，避免降低验收可审计性。

第一阶段保持目标项目代码和配置只读，但四阶段交接都必须落盘为 JSON。每次覆盖当前文件前，把旧版本关联到迭代记录。除非仓库已有约定或用户明确要求，不提交这些生成物。

## 需求模式失效与完成

需求模式按 `09-需求驱动交互闭环.md` 聚合多个页面状态机。产品契约变化需重新审查实现与用例；共享逻辑变化使所有受影响页面/流程证据失效。仅某页 complete 不代表产品 complete；产品还需功能结果及聚合门禁通过。


## 响应式产物失效补充

启用响应式时，固定稿 Frame 身份、固定稿源码/资产/默认态或共享组件变化，会使响应式计划依赖的捕获、基准回归、diff、audit 和 `responsive-validation.json` 失效；响应式专属样式变化只使受影响的响应式证据失效。任何共享资产或共享组件变化都必须同时回归固定稿和响应式。
