# 响应式适配闭环

本规则只在用户明确要求响应式、提供多个 viewport 设计稿，或需求契约明确要求多端适配时加载。默认 `fixed_only` 不改变既有固定尺寸流程。

## R1 模式与边界

响应式不是把整张页面缩放到浏览器里，而是以固定稿为只读基准，在明确的 viewport 范围内按组件规则改变布局。

```json
{
  "layout_mode": "fixed_only | fixed_and_responsive",
  "responsive": {
    "base": { "width": 375, "height": 812, "source": "figma_frame" },
    "viewport_range": { "min_width": 320, "max_width": 440, "min_height": 568, "max_height": 932 },
    "viewports": [{ "width": 320, "height": 700, "kind": "min" }],
    "breakpoints": [],
    "out_of_range_behavior": "centered_max_content | min_canvas_scroll | not_supported"
  }
}
```

`base.width` 必须等于固定稿 Frame 宽度。没有对应设计稿的宽度可以验证布局规则，但不能伪造像素还原率。支持的范围、断点和超范围行为必须在第一阶段计划中明确；不得默认把一个端型推导成所有端型。

## R2 组件适配合同

第一阶段对布局组件和复杂视觉组建立 `responsive_component_contracts`。普通子节点继承父组件规则，不要求逐个图层重复登记。每项至少说明：

- `strategy`: `anchored | fluid | content_reflow | layout_reflow | proportional | fixed_overlay`；
- `parent_id`、`base_geometry`、`fixed_regions`、`fluid_regions`；
- 最小/最大尺寸、文字换行与溢出、图片比例和裁切规则；
- 断点前后行为、交互点击区域、验证宽度和证据；
- 异形外壳只允许拉伸有证据的中段，人物和复杂视觉保持比例。

禁止使用根容器整体 `transform: scale()` 冒充响应式。局部图片或装饰组合可以按比例缩放，但必须保持原始比例；已合成进资产的旋转、镜像、阴影和混合效果不得在 CSS 中重复应用。

## R3 四阶段接入

1. **第一阶段**：固定 Frame 身份后，先形成端型、范围、组件策略和 viewport 计划；证据缺失进入补读队列，不因端型暂为 `pending_evidence` 而死循环。
2. **第二阶段**：只补读 Auto Layout/约束、父子锚点、文字换行、图片裁切区和异形可伸缩区；资产继续复用现有 manifest 与 QA。
3. **第三阶段**：先完成原始尺寸固定稿并通过基准门禁，再实现独立响应式入口。响应式可以共享业务数据、交互和已通过 QA 的资产，但样式/布局证据必须可区分；基准实现不能被静默改写。
4. **第四阶段**：分别验收固定稿、响应式基准回归和多 viewport 适配。运行 `scripts/validate-responsive.mjs`，其通过结果才可作为最终 `can_deliver` 的响应式子门禁。

固定稿代码、资产、默认态或 Frame 身份变化时，响应式截图、diff、audit 和门禁全部失效，按既有状态机回退。响应式代码变化时，仅失效受影响的响应式证据，但共享资产或组件变化必须同时回归固定稿。

## R4 验收协议

默认 viewport 不是设备身份的硬编码；下面是可采用的预设：

- `mobile_portrait`: 320、360、375、390、414、430、440；
- `mobile_landscape`: 812、844、896、915、932、956；
- `desktop`: 1024、1280、1366、1440、1600、1920。

每个响应式任务至少包含：基准宽度、范围最小值、范围最大值、一个中间宽度、每个实际断点前后 1px，以及一个范围外安全预览宽度。每个捕获记录 viewport 宽高、根节点实际尺寸、截图/捕获报告路径、控制台和网络错误、横向溢出、核心内容裁切、根缩放和交互默认态。

范围内检查布局连续变化；范围外只验证页面可访问且不崩溃，不宣称该范围已经适配。页面高度可以随内容自然增长，不能为了匹配固定截图而锁死或静默裁切。短视口必须检查固定底部操作区是否遮挡内容。

## R5 人工复核和交付

普通容器伸缩、换行和锚定由 AI 按证据直接执行。只有多个方案都会成立且会明显改变构图时创建局部 `reviewGate`，状态为 `pending -> approved -> applied -> verified -> resolved`；未解决的 gate 阻断交付。

最终交付条件为：

```text
fixed_gate_passed
AND (layout_mode == fixed_only OR responsive_gate_passed)
AND product_gate_passed（仅需求模式）
```

响应式证据必须保存于当前 `run_dir`，并使用稳定本地路径，不使用会过期的临时 Figma URL。
