# 第一阶段数据契约

执行第一阶段时与 `03-公共状态契约.md` 一起读取。本文件定义 `stage-1-handoff.json` 的 `handoff` 内容。

## P1 总结构

```json
{
  "handoff": {
    "design_analysis": {
      "task_meta": { "report_profile": "compact | full" },
      "frame_info": {},
      "page_overview": {},
      "layout_structure": { "sections": [] },
      "layer_hierarchy": { "root_id": "", "nodes": [], "coverage": {} },
      "typography": { "text_layers": [], "font_availability": [] },
      "color_system": { "solid_colors": [], "gradients": [], "variables": [] },
      "spacing_system": { "page_padding": {}, "section_gaps": [], "component_spacing": [] },
      "shape_styles": { "corners": [], "borders": [], "dividers": [] },
      "effects": { "shadows": [], "blurs": [], "blend_modes": [], "opacities": [] },
      "assets": { "inventory": [], "original_images": [], "required_exports": [] },
      "code_restore_plan": {},
      "export_plan": {},
      "risk_points": [],
      "verification_checklist": [],
      "specialized_inventories": {}
    }
  }
}
```

## P2 Frame、页面与 section

`frame_info` 必含身份、坐标、CSS/像素尺寸、倍率、背景、状态栏/导航/安全区、滚动与完整截图。`page_overview` 必含页面类型、复杂度、风格、主要区域、固定尺寸策略、长页真实高度和默认状态。

每个 `section` 使用下列唯一规范字段：

```json
{
  "section_name": "hero",
  "x": 0,
  "y_start": 0,
  "y_end": 420,
  "width": 375,
  "height": 420,
  "included_layer_ids": [],
  "background_layers": [],
  "text_layers": [],
  "image_layers": [],
  "decoration_layers": [],
  "button_layers": [],
  "card_layers": [],
  "export_groups": [],
  "restore_strategy": "",
  "overlaps": [],
  "risks": []
}
```

上述 `sections` 是唯一规范 section 来源，必须用 `section_name/y_start/y_end` 从 0 连续覆盖到 Frame 高度，不重叠、不留空。跨区元素以 `overlaps` 说明视觉归属。默认不再复制为独立 `sections.json`；diff 和 Stage 4 生成器直接读取 Stage 1 交接。`name/yStart/yEnd` 与独立数组文件只作为旧产物导入兼容，不得继续写入新交接物。

## P3 图层与文本

`report_profile=full` 时另读 `04-完整报告扩展.md`，按其逐节点字段执行。

`report_profile=compact` 时，只对结构根、文本、交互、资产根和风险节点输出上述完整字段；分类唯一事实源是 `layer_hierarchy.coverage.classified_layer_ids_by_strategy`，其中必须按五种策略枚举全部可见 ID。紧凑输入只需显式提供 `unknown_role_count`（无未知项时可省略并按 0 处理）；生成器从分类并集派生 `classified_visible` 和 `total_visible`，并拒绝重复 ID 或与显式计数不一致的输入。紧凑模式可以减少逐节点重复字段，但不能漏 ID、漏 section、漏实现分类或隐藏风险。

紧凑模式的文本项记录 ID、内容、bbox、行数/换行、字体、字号、字重、行高、颜色/效果、实现策略和证据；存在富文本、描边、旋转、特殊字体或视觉冲突时再展开 run/span 与完整字段。普通 span 必须 `real_text`，只有最小特殊字体片段可标资产。

## P4 专项清单

紧凑模式把专项检查写为 `checked`、`findings` 和 `not_applicable` 三组，列出实际检查项即可，不为每个不适用类别生成独立空对象。完整模式另读 `04-完整报告扩展.md` 并输出固定专项结构。

## P5 第一阶段 `handoff`

```json
{
  "handoff": {
    "design_analysis": {},
    "page_classification": {},
    "readiness_score": {
      "frame": 0,
      "layer_tree": 0,
      "typography": 0,
      "styles": 0,
      "assets": 0,
      "mask_boolean_transform": 0,
      "sections": 0,
      "layer_coverage": 0,
      "export_grouping": 0,
      "risk_documentation": 0,
      "overall": 0
    },
    "restore_fidelity": { "stage": "estimated", "range": "", "evidence": [] },
    "sections": [],
    "layer_coverage_risks": [],
    "mask_boolean_transform_risks": [],
    "targeted_reread_queue": [],
    "blocking_reasons": [],
    "can_enter_stage_2": false
  }
}
```

紧凑交接默认省略顶层 `real_text_layers`、`code_css_layers`、`svg_layers`、`png_layers` 和 `ignored_layers`，消费者从 P3 的分类唯一事实源读取。只有明确兼容旧消费者时才由生成器加 `--legacy-classification-mirrors true` 输出全部五个镜像；镜像必须成组存在且逐项匹配。`report_profile=full` 仍按完整报告契约保留顶层分类数组。

补读队列每项包含 `node_id`、字段、P6 缺失类型、关键性、来源、置信度、依赖、最小补读范围和预期证据。

## P6 报告档位

默认使用 `compact`，满足以下任一条件才使用 `full` 并加载 `04-完整报告扩展.md`：用户明确要求“深度读取/完整审计/全量节点”；长页或复杂活动页；超过 3 个 section；超过 50 个可见节点；根读取截断；结构与最终视觉冲突；无法用覆盖索引证明完整性。

紧凑交接写入 `stage-1-handoff.json`。生成器输出按 minified JSON 计算的 `compact_bytes`，并把默认 12288 bytes 仅作为体积建议阈值：超限只给出非阻塞 warning，不影响输出、退出码、校验、readiness 或 `can_enter_stage_2`。不得仅因该 warning 压缩/删减事实、创建 `--details` 附件或重复生成；只有任务本身需要独立正式分析附件时才使用 `--details <stage-1-analysis-details.json>`。回复仅返回状态、关键风险、耗时和路径。

把上述 `handoff` 事实和 `run_id` 先写入 `/tmp/figma-to-code/<run_id>/stage-1-input.json`，再用 `scripts/generate-stage1-handoff.mjs` 与参考图、计时和可选分析附件生成正式交接；生成器派生参考图 SHA-256、覆盖计数和 `can_enter_stage_2`，禁止手工重复维护公共外壳、状态、哈希和 timing。写入后运行 `scripts/validate-handoff.mjs --file <run-dir>/stage-1-handoff.json`；该统一校验器同时执行第一阶段专项覆盖复核。分类 ID 去重并集必须等于 `classified_visible`，`classified_visible + unknown_role_count` 必须等于 `total_visible`；section 必须连续覆盖 Frame 高度且覆盖除根节点外的全部分类 ID。校验失败时留在第一阶段修正事实输入，不得靠提高分数或声明覆盖完整绕过。


## 响应式字段（仅启用时）

`handoff.layout_mode` 为 `fixed_only | fixed_and_responsive`。启用后，`handoff.responsive_plan` 至少包含 `base`、`viewport_range`、`viewports`、`breakpoints`、`out_of_range_behavior` 和 `responsive_component_contracts`；详细组件事实只放在引用文件中时，必须提供路径与哈希。
