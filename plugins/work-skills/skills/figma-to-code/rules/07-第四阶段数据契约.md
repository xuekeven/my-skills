## V2 十类 audit

完整内容只写入 `stage-4-audits.json`，由 `scripts/generate-stage4-report.mjs` 生成。简单页面使用聚合 item；复杂页面由 assessment 提供详细覆盖。两种模式都必须保留以下 10 个键：

```json
{
  "machine_executable_audits": {
    "layer_coverage_audit": { "items": [], "missing_layers": [] },
    "rich_text_run_plan": { "items": [] },
    "text_outline_audit": { "items": [] },
    "button_icon_audit": { "items": [] },
    "background_illustration_inventory": { "items": [] },
    "gradient_direction_audit": { "items": [], "edge_samples": [] },
    "mask_blur_clip_audit": {
      "mask_boolean_transform_audit": { "items": [] },
      "nested_blur_shape_inventory": { "items": [] }
    },
    "z_index_layer_order_audit": { "items": [] },
    "asset_size_audit": { "items": [] },
    "visual_diff_report": { "can_accept": false }

```

这 10 个键必须全部存在；空页面类别也要有 `not_applicable_reason`。`stage-4-handoff.json` 不复制这些条目，只引用 audit 文件及其哈希、数量和状态汇总。

每个 finding 使用第四阶段 V6 根因枚举，并带区域、严重度、证据、负责阶段、状态和复验结果。

`input_artifacts` 至少引用有效的 Stage 1、`stage-3-handoff.json`、Figma 参考图、当前预览截图和当前捕获报告；`output_artifacts` 引用 `stage-4-visual-diff-report.json`、`stage-4-diff.png`、`stage-4-audits.json` 与 `stage-4-iteration-history.json` 及哈希。section 默认直接读取 `stage-1-handoff.json#handoff.design_analysis.layout_structure.sections`，不生成独立 `sections.json`；读取器兼容旧版顶层 `design_analysis`，只有更早的独立数组产物才传 `--sections`。Stage 3 默认使用 `stage-3-preview.png`/`stage-3-capture-report.json`；第四阶段重拍时使用 Stage 4 前缀，禁止覆盖上游证据。

生成器写入后，由 `validate-handoff.mjs` 打开引用文件并确认 10 类 audit 键齐全、评分公式输入存在、当前截图/捕获/diff 哈希匹配、无回归错误；任一门禁失败时 `can_deliver=false`。不要为了“自包含”把完整 audit、评分明细或迭代记录再次复制进 handoff。

## V5 模式与 assessment

- `auto` 只在 Stage 1 fast path、可见图层 `<=40`、section `<=4` 且捕获/diff 通过时选择 `compact`。
- `compact` 的聚合 audit 必须能由上游结构、manifest、捕获或 diff 直接证明。
- 其他页面使用 `detailed`。assessment 只保存脚本无法确定的 10 类 audit 覆盖、finding、评分覆盖、风险决策和回归结果，不维护公共外壳或哈希。
- Stage 3 `known_risks` 默认阻塞；只有显式 `--accept-known-risk <type>` 或 detailed assessment 给出证据与消除条件后才可交付。


## 响应式交付门禁（仅启用时）

`handoff.responsive_validation` 引用 `responsive-validation.json`。最终 `can_deliver` 必须同时满足固定稿现有门禁和响应式 `can_deliver=true`；不得用固定稿单尺寸 diff 替代多 viewport 适配验收。
