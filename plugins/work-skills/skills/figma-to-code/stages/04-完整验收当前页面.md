## V1 进入条件与基线

- `workflow_state.status=stage_3_implemented`，或正在同一 `run_id` 的 `stage_4_validating` 循环。
- 页面、独立路由、捕获根、Frame CSS 尺寸、Figma 参考图、Stage 1 section 和 manifest 可用。
- 已有服务或静态 `file://` 页面能稳定打开目标 URL，无阻塞运行时错误；服务不可用时服从 `SKILL.md` 的服务启动门禁，不自行启动。
- 再次核对文件 key、Frame ID 和宽高；变化时回第一阶段。

单独执行本口令时，从交接文件恢复身份。缺参考图、尺寸、资产或稳定页面时按 `../rules/02-状态机与闭环回退.md` 回退补齐，不能对任意截图给出还原度。

若页面必须依赖未运行的服务，记录 `preview_service_not_running`、所需命令和恢复条件，停止浏览器相关计时并等待用户主动要求启动；禁止用启动服务规避该等待，也禁止降低验收门禁。

建立验收基线：记录参考图哈希、Frame 尺寸、共同倍率、URL、捕获根、视口、字体/图片加载、滚动位置、默认交互状态，以及连续覆盖 `0..FrameHeight` 的 section 坐标。每轮修改前记录基线截图、diff、已通过区域、目标文件和目标区域。

Stage 3 已有规范证据且实现/默认态未变化时，只读复用 `stage-3-preview.png` 与 `stage-3-capture-report.json`。需要重拍时使用 `stage-4-preview.png` 与 `stage-4-capture-report.json`；禁止写回 Stage 3 文件或复用被覆盖后的历史哈希。

参考图只用于验收，不得被页面代码引用。

## V2 截图前置

### V2.1 捕获

只截还原根容器或精确 Frame，不截浏览器 UI、外围居中容器或额外空白。可运行：

```bash
node <skill目录>/scripts/shoot-preview.mjs \
  --url <预览URL> \
  --out <stage-4-preview.png> \
  --report <stage-4-capture-report.json> \
  --width <Frame宽> \
  --height <Frame高> \
  --scale <共同倍率> \
  --capture-target <唯一CSS选择器>
```

脚本必须查询并直接捕获 DOM 根；捕获根不存在、不唯一或尺寸不符时立即失败，不允许退回手工 `align/crop-x` 后声称已程序化对齐。

### V2.2 强制前置项

- 参考图与预览图像素尺寸都精确等于 `Frame CSS尺寸 × scale`；
- 两图宽高、倍率完全相同，没有缩放、静默裁切、补白或额外空间；
- 捕获根唯一且 bbox 等于 Frame CSS 尺寸；截图 clip 精确等于该 bbox，因此输出图 `(0,0)` 对应根容器左上角；
- 字体和图片已加载，截图不是空白、loading、错误页或动画中间态；
- 默认交互状态与 Figma 一致；该项是有证据的语义断言，不得标成脚本机器检查；
- 长页完整捕获，每个 section 均在图中且坐标连续。

`shoot-preview.mjs` 机器记录根 bbox、裁切范围、字体/图片/loading 状态、空白图检查和截图哈希。任一机器项失败，或默认态断言不是 `pass` 时 `can_run_diff=false`，写入对应错误。只修捕获配置或默认态，不输出 diff 结论、像素匹配率或实测还原度。

## V3 程序化 diff

前置通过后运行：

```bash
node <skill目录>/scripts/visual-diff.js \
  --reference <figma-reference.png> \
  --actual <stage-3-preview.png|stage-4-preview.png> \
  --out <stage-4-diff.png> \
  --report <stage-4-visual-diff-report.json> \
  --width <Frame宽> --height <Frame高> --scale <共同倍率> \
  --capture-report <stage-3-capture-report.json|stage-4-capture-report.json> \
  --default-state-checked true \
  --default-state-evidence <默认态截图或audit证据> \
  --sections <stage-1-handoff.json> \
  --threshold 0.3 \
  --accept <整体差异上限> \
  --section-accept <分区差异上限>
```

- 验收评分使用颜色阈值 `0.3`；整体/section 接受上限使用项目既有标准或本轮开始前声明的口径，不能为通过临时放宽。
- 默认直接传 Stage 1 交接，读取 `design_analysis.layout_structure.sections` 的 `section_name/y_start/y_end`。独立 section 数组与 `auto` 只用于旧流程兼容。
- 复杂长页必须使用 Stage 1 的真实 section，不能只看整体或自动三等分。
- 保存参考图、预览图、diff 图、整体差异、像素匹配率、section 差异和最高差异区域。
- 脚本退出码 `3` 是前置失败、`2` 是差异超阈值、`0` 才是机器阈值通过。
- `possible_issue` 只是启发式定位，必须由结构化 audit 复核，不能直接当根因。

程序化 diff 只回答“哪里不同”，不能替代元素覆盖、文字、资产、层级和效果审计。

## V4 十类结构化 audit

所有 audit item 至少包含 `layer_id/layer_name`、`expected`、`actual`、`status(pass|warn|error)`、证据和 `fix_strategy`。以下 10 类缺一不可：

1. `layer_coverage_audit`：全部可见层、section 与已解释不可见层；可见缺失为 error。
2. `rich_text_run_plan`：所有富文本 run/span、样式隔离、特殊字体片段；漏拆、拍平或整段图片化为 error。
3. `text_outline_audit`：fill/stroke/effect stack；仅描边文字被填实、fill/stroke 冲突或效果丢失为 error。
4. `button_icon_audit`：按钮容器/底/边/影/图标/文字、图标类型/资产策略/尺寸/gap/居中；缺失或错位为 error。
5. `background_illustration_inventory`：背景插图、半露元素、边缘装饰和低透明层；缺失为 error。
6. `gradient_direction_audit`：背景和描边的类型、向量、stop、角度及 8 点边缘采样；反向或采样不符为 error。
7. `mask_boolean_transform_audit` + `nested_blur_shape_inventory`：蒙版、布尔、clip、crop、镜像、旋转、负缩放、blur/柔光、父级裁切和层级。
8. `z_index_layer_order_audit`：视觉顺序、stacking context、blend 隔离、前后遮挡；任何关键顺序错误为 error。
9. `asset_size_audit`：源节点、格式、倍率、像素/显示尺寸、比例、alpha、边界、placement 和哈希；模糊、变形、过大位图或哈希过期为 error。
10. `visual_diff_report`：前置、整体/section 差异、高差异区域和 `can_accept`。

同时核对：

- Frame/section 坐标、尺寸、间距、长页高度和滚动；
- 文本内容、换行、字体、行高、字距、颜色、描边、倾斜和基线；
- 圆角、边框、阴影、blur、毛玻璃、分层 opacity 和 blend mode；
- 卡片混合策略、手写线、分割线、标题强调线和角标锚点；
- 普通文字/切图文字互斥、默认状态和范围内必要交互；
- lint、类型、测试、构建、运行时和控制台回归。

存在 `status=error` 未解决项时对应 audit 不通过；error 的 `fix_strategy` 不得为空。估算项保留来源、置信度、风险和确认要求。

### V4.1 自动生成模式

优先使用 `scripts/generate-stage4-report.mjs`，不要手写 10 类 audit 或在 handoff 中复制详细条目。

- `auto`：Stage 1 `fast_path=true`、可见图层不超过 40、section 不超过 4、捕获和 diff 均通过时自动选择 `compact`；脚本从上游图层映射、manifest、当前捕获与 diff 生成每类聚合 item。
- `compact`：只适用于上述简单页面条件。允许用可重复的 `--accept-known-risk` 接受已有低风险；脚本无法确认的视觉问题必须通过可选 assessment 覆盖，不能口头忽略。
- `detailed`：复杂页面、门禁失败、局部修正循环或存在视觉判断冲突时使用。assessment 必须显式覆盖全部 10 类 audit；生成器仍负责公共字段、哈希、评分公式和文件引用。

详细 audit 只写入 `stage-4-audits.json`；`stage-4-handoff.json` 只保存该文件的路径、哈希、通过/警告/错误数量和最终门禁。

## V5 多维评分与还原度

### V5.1 基础评分

每项 `0–100`，由 audit 和 diff 证据支持：

`frame_size_accuracy`、`section_position_accuracy`、`layer_order_accuracy`、`background_illustration_completeness`、`text_content_accuracy`、`text_wrap_accuracy`、`typography_weight_accuracy`、`card_surface_accuracy`、`gradient_mask_effect_accuracy`、`border_gradient_accuracy`、`micro_anchor_accuracy`、`asset_ratio_accuracy`、`texture_fidelity_accuracy`、`interaction_button_accuracy`、`overall_visual_match`。

以下任一项 `<95` 不能完成：`layer_order_accuracy`、`background_illustration_completeness`、`text_wrap_accuracy`、`card_surface_accuracy`、`micro_anchor_accuracy`、`overall_visual_match`。

### V5.2 细节评分

追加：`gradient_direction_accuracy`、`gradient_border_sampling_accuracy`、`title_underline_baseline_accuracy`、`nested_blur_shape_completeness`、`nested_effect_clip_accuracy`、`text_segment_strategy_accuracy`、`special_font_asset_accuracy`、`mixed_text_alignment_accuracy`。

- `gradient_direction_accuracy` 和 `title_underline_baseline_accuracy` 必须 `>=98`。
- `nested_blur_shape_completeness`、`text_segment_strategy_accuracy`、`special_font_asset_accuracy` 必须 `>=95`。
- `overall_visual_match <98` 时必须继续循环；不可用不可约差异例外绕过 98 分门槛。

### V5.3 综合还原度

按固定口径计算：

```text
R_pixel = 100 - overall_diff_percent        // visual diff threshold = 0.3
R = round(0.6 * R_pixel + 0.4 * overall_visual_match)
```

输出 `restore_fidelity.stage=measured`、本轮 `R`、上一轮值、变化量、像素匹配、多维分解、可修偏差与预计提升、不可约扣分与消除条件。

简单页面的基础分、细节分与公式由 `generate-stage4-report.mjs` 从 audit/diff 自动计算。只有详细模式允许 assessment 覆盖脚本无法推导的维度；覆盖值仍必须经过生成器和 `validate-handoff.mjs` 的阈值与公式复核。

等级：

- `<90%`：不合格，继续修正；
- `90–<95%`：仍需局部优化；
- `<98%`：不可交付；存在可修差异时继续循环，存在不可约差异时记录并阻断。
- `>=98%`：满足其他机器门禁、audit、关键维度和回归条件后即可交付；如仍有低优先级可修差异，保留证据并暂停继续修正。

不得只给一个主观百分比，也不得把字体抗锯齿、backdrop-filter、浏览器渲染或抠图羽化伪装成已消除。

## V6 根因修正循环

### V6.1 Finding 与归因

每个 finding 记录区域、严重度、期望、实际、证据、根因、负责阶段、修正状态和复验结果。根因使用：

- `frame_changed`
- `source_field`
- `asset_export`
- `code_layout`
- `code_style`
- `capture_precheck`
- `irreducible_rendering`

每轮按以下问题组汇总：`layer_order_issues`、`missing_background_illustration_issues`、`card_surface_effect_issues`、`text_wrap_issues`、`micro_anchor_issues`、`asset_ratio_issues`、`invented_layer_issues`、`gradient_mask_effect_issues`、`section_alignment_issues`、`remaining_minor_issues`。

### V6.2 循环顺序

1. 先处理 blocking、漏元素、层级错误和大面积偏移。
2. 按 `../rules/02-状态机与闭环回退.md` 回到根因阶段，只修受影响节点、资产、组件或捕获配置。
3. 修改后重新运行适用代码检查，重新截图、前置、diff、全部受影响 audit 和评分。
4. 对比上一轮：已消失、仍存在、新增、分数变化和是否继续。
5. 新问题标 `regression_error`，优先恢复已通过区域。

每轮都必须重新截图和输出问题清单。同一指标连续 3 次针对性修正无改善时重新判断根因，不能重复堆同类 CSS 补丁。错误资产不能靠 CSS 补，错误字段不能靠最终偏移掩盖，捕获错误不能算页面差异。

## V7 停止与交付门禁

只有同时满足以下条件，状态才可转 `complete`：

1. diff 前置全部通过，整体和每个 section 均在声明阈值内；
2. 10 类 audit 全部产出，无未解决 `status=error`、blocking 或可修高优先级项；
3. 无漏元素、层级错误、背景插图缺失、主要文字/富文本/描边错误、渐变反向、卡片/按钮/角标错误；
4. 重要 bbox 误差 `1–2px`，非核心装饰不超过 `3px`；
5. V5 的所有关键维度达到阈值；
6. `R>=98`；低于 98 分不得以不可约差异例外交付；
7. manifest、实现引用、哈希一致，代码/构建/运行/滚动/默认交互无回归；
8. 本轮没有 `regression_error`，旧截图、旧 diff 和回退前评分未被当作当前证据。

综合还原度低于 98 分时，存在可修差异必须继续循环；达到 98 分及以上即可交付并暂停继续修正。暂停时必须保留剩余差异、证据、影响和消除条件，不得用“肉眼差不多”替代评分和门禁。

关键来源、工具或用户决策确实不可得且安全替代路径已耗尽时，状态为 `blocked`；列出尝试、证据和恢复条件，不伪装完成。

## V8 最终报告

先运行 `scripts/generate-stage4-report.mjs --help`。完成捕获、diff、必要的人工视觉判断和回归后，一次生成三份正式文件：

```bash
node <skill目录>/scripts/generate-stage4-report.mjs \
  --stage1 <stage-1-handoff.json> \
  --stage3 <stage-3-handoff.json> \
  --manifest <asset-manifest.json> \
  --capture-report <stage-3-capture-report.json|stage-4-capture-report.json> \
  --reference <figma-reference.png> \
  --preview <stage-3-preview.png|stage-4-preview.png> \
  --visual-diff <stage-4-visual-diff-report.json> \
  --diff-image <stage-4-diff.png> \
  --timing <timing.json> \
  --output <stage-4-handoff.json> \
  --mode auto
```

生成器默认从 `--stage1` 读取 section，不生成或引用独立 `sections.json`。只有兼容旧数组或显式使用另一份 Stage 1 交接时才传 `--sections <path>`。有 Stage 3 已知风险时逐项决定；只对有证据且满足 V7 的项传 `--accept-known-risk <type>`。复杂页面改用 `--mode detailed --assessment <json>`。

生成后运行 `scripts/validate-handoff.mjs --file <stage-4-handoff.json>`。停止阶段计时后只需重跑生成器和校验器一次以固化最终计时；不得手工重算或复制字段。最终回复只给结论和文件路径。

`stage-4-handoff.json` 的引用链必须覆盖：

- Figma 文件、Frame ID、名称、CSS 尺寸和倍率；
- 预览 URL、路由、捕获根和默认态；
- 修改文件、正式资产及真实文本/CSS/PNG/SVG 分类；
- 实际运行的检查命令、退出码和结果；
- 前置结果、参考/预览/diff/报告路径、整体和 section 差异；
- `stage-4-audits.json` 的哈希、10 类状态摘要与剩余 finding 数量；
- 多维评分摘要、固定公式、综合还原度和相对上一轮变化；
- 回退/修正轮次、回归证明、不可约差异与消除条件；
- 最终 `workflow_state`、`can_deliver` 和阻塞/风险。

## V9 禁止事项

- 禁止只肉眼验收一次、只报总百分比或省略结构化 audit。
- 禁止在尺寸、倍率、裁切、空白或对齐失败时运行/解释 diff。
- 禁止缩放参考图、静默裁切、隐藏差异、临时放宽阈值或删除检查项。
- 禁止整页重构、修改无关区域、覆盖用户改动或为一个局部问题破坏已通过区域。
- 禁止使用回退前截图、旧 manifest、旧 diff 或旧评分作最终证据。
- 禁止手工展开可由生成器确定的 audit、哈希、评分、迭代和公共交接外壳，也禁止把 `stage-4-audits.json` 全量复制进 handoff。
- 禁止提交或推送 Git，除非用户明确要求。

## V10 需求模式产品验收

加载 `../rules/09-需求驱动交互闭环.md` 与 `../references/需求契约与功能验收.md`。先完成每个设计页面的上述视觉流程，再执行需求用例和跨页回归，运行 `validate-product.mjs` 生成产品结论，再运行 `generate-ui-ux-report.mjs` 生成交付根目录下的 `ui-ux-report.md`。单页 can_deliver 只代表视觉子门禁；产品交付还必须功能全部通过、证据未过期且无阻塞澄清。不能通过删交互、冻结真实时钟或降低测试覆盖修复 diff。


## 响应式模式补充

启用响应式时分别保存固定稿验收、响应式基准宽度回归和多 viewport 适配证据。运行：

```bash
node <skill目录>/scripts/validate-responsive.mjs \
  --input <run-dir>/responsive-plan-and-results.json \
  --output <run-dir>/responsive-validation.json
```

只有 `responsive-validation.json.can_deliver=true` 才能满足响应式子门禁；范围外宽度只检查可访问和不崩溃，不宣称已适配。页面自然增高是允许的，禁止用锁高或静默裁切制造固定截图。
