## A1 进入条件

- `workflow_state.status=stage_1_planned`。
- 第一阶段已提供精确身份、最终视觉、分析 JSON、读取评分、补读队列和切图分组计划。
- 开始前重新确认文件 key、Frame ID 和尺寸；变化时回第一阶段。

单独执行本口令时，前置交接缺失就先补齐最低限度的第一阶段；不得根据截图直接猜字段或切图。

## A2 定向补读闭环

### A2.1 每轮步骤

逐项处理 `targeted_reread_queue`：

1. 先按最小相关子树和所需能力合并队列；同一子树可共同返回的字段只读一次，互不依赖的目标可并行。
2. 用 P6 的错误类型确认是源节点无属性、连接器漏返/截断、来源冲突、只能视觉推断还是原资产不可取。
3. 先读合并后的最小相关节点；涉及父级继承、蒙版、布尔、层级、组件 override 或混合时扩大到最小相关子树。
4. 交叉核对结构化字段、最终视觉、节点导出、原始图片、仓库已有正式资产和用户确认。
5. 更新字段值、来源、置信度、证据、依赖计划和本轮变化；不丢弃已确认信息，不重读未受影响字段。
6. 输出本轮目标、成功字段、仍缺字段、来源变化、置信度变化、完整度和 blocking。

视觉辅助可以判断漏元素、渐变方向、描边/柔光是否存在和粗略位置，但不能替代结构数据、创造图层或把估算写成确定值。

### A2.2 轮次和停止

同一字段最多定向补读 3 轮：

- `>=95` 且无 blocking：正常停止补读。
- `90–<95` 且缺失均为非关键：可 `generate_with_risk`，保留每个估算风险。
- 连续 3 轮仍无法取得非关键字段：可转视觉估算，来源和置信度不得伪装。
- 连续 3 轮后关键字段仍 `blocking`：状态转 `blocked`，要求用户确认、重新选择画板或恢复数据能力。
- `<90`：禁止进入代码阶段。

关键 bbox、文本内容/折行、关键渐变、关键蒙版边界、层级和资产边界不能用 `low` 放行。

## A3 资产边界决策

### A3.1 可打组导出的内容

- 人物/IP 与不可拆的光效、阴影、配件；
- 插画与共同构成语义的装饰、纹理、光芒；
- 复杂艺术字与其描边、发光、勋章等最小完整标题视觉组；
- 含位图、复杂 blur、玻璃、混合模式、复杂 stroke 或光影且代码无法稳定复现的合成组；
- Figma 中经过蒙版、布尔或复杂变换后必须保持最终视觉的组。

### A3.2 不得吞入资产的内容

- 正文、普通标题、标签和按钮文字；
- 简单纯色/规则渐变背景、规则卡片、按钮、输入框和分割线；
- 可独立复用的系统矢量图标；
- 本应响应内容变化的控件；
- 仅为方便而加入的整张卡片、整个 section 或整个 Frame。

特殊字体按文本片段切最小边界；不能因为一句话里有一个艺术字而切整段，更不能切整卡片。普通文字与切图文字必须互斥，防止重复渲染。

### A3.3 最终视觉与用户覆盖

蒙版、布尔、隐藏辅助层、镜像、旋转和负缩放按最终视觉决定包含内容与方向。图层名称或分组和最终视觉冲突时，补读并记录依据。

用户指定组合优先。例如“勋章、光芒、艺术字作为整体 3 倍 PNG，勋章下方 bg 用代码”：前三者必须属于同一 `content_layers`，背景必须属于 `excluded_layers` 与 `code_css_layers`，不得拆分或误吞。

## A4 格式、倍率与边界

### A4.1 格式决策

- 独立系统图标、路径、简单矢量插画：优先 SVG。
- 含位图、复杂 blur/玻璃、混合模式、复杂描边、阴影或发光的视觉组：PNG，不强行 SVG。
- 复杂透明视觉组：默认 PNG 3x；明确只需普通高分屏时可 2x，用户指定倍率时遵从用户。
- 位图、照片、3D 渲染：优先原始上传图或无损原格式；不能为方便从截图裁。
- 特殊艺术字：纯矢量/描边/渐变且可 outline 时优先 SVG；含栅格效果或复杂合成时 PNG 3x。
- JPG/WebP 只用于本来就不需要 alpha 且有损压缩不产生可见损失的普通图片。

格式必须在首次正式导出前确定。结构化数据证明节点只含矢量、渐变、滤镜、mask、clipPath 和可 outline 文本时，直接导最小 SVG；不得先导 PNG 再试错。只有 SVG 无法忠实承载位图、混合或栅格效果时才进入 PNG 路径。

用户要求 PNG，但视觉组完全由矢量、滤镜和 outline 文字构成时，仍先取得透明 SVG 组件并在目标导出画布内一次栅格化为 PNG。不要先导 Figma 组 PNG 再检查是否被注入白底或 matte；只有结构中确有位图或 SVG 无法承载的混合效果时才直接导组 PNG。

### A4.2 边界和安全留白

每项记录：源节点、逻辑 bbox、最终视觉 bbox、效果溢出、导出画布 bbox、安全 padding、倍率、像素尺寸和页面 placement。

- 安全留白由阴影、发光、blur、描边和抗锯齿的真实溢出决定，不使用无依据的大画布。
- `pixel_size = export_canvas_css_size × scale`，必须精确相等。
- 页面显示尺寸使用设计 CSS 尺寸；不得把 3x 像素尺寸当 CSS 尺寸。
- placement 要补偿安全 padding，不用拉伸、额外裁切或错误 `object-fit` 掩盖。
- 保持源宽高比。需要裁切时记录 Figma 的 crop/蒙版，不在页面临时猜裁切。

## A5 透明底治本

### A5.1 先识别根因

部分导出链会向节点结果注入灰色 matte、父画板白色背景或节点白底；这不是源图层内容。必须比较源节点、导出结构和四角 alpha，确认白底来自源内容还是导出注入。

### A5.2 决策顺序

1. 矢量/艺术字：优先 SVG；只删除确认由导出链注入的灰 matte 和整幅画板白色背景 rect。
2. 位图/照片/3D 图：优先取得原始 `rawImages` 或等价原图，保留天然 alpha。
3. 复杂混合组无法拆开时：导出 PNG，并验证 alpha 与容器背景。
4. 上述透明源确实不可取得时才允许色键/抠图；必须记录羽化风险和不可约扣分。禁止用 `mix-blend-mode:multiply` 掩盖可治本的白底。

清理 SVG 时必须保留 mask 内的白色、带 `fill-opacity` 的内容 rect 和真实图形；只依据颜色全局删除会破坏资产。灰色 `#666666` 或整幅 white rect 也只能在结构和尺寸证明它是注入背景时删除。

### A5.3 唯一 matte 特例

复杂位图组没有透明源，且 matte 颜色与资产所在容器的纯色底完全相同、任何位置都不可见时，可有证据地放行。此时不得再用 CSS 圆角二次裁掉资产自带真实圆角。matte 与容器不一致一律不放行。

## A6 导出执行

1. 从 Figma 原始节点、原始图片或用于精确边界的临时导出组导出；不得从参考图或页面截图裁片。
2. 临时组只能定义导出边界，不能改变层级、blend、opacity、蒙版、变换或内容。
3. 候选和逐资产临时 QA 一律写入 `/tmp/figma-to-code/<run_id>/stage-2-candidates/<asset_id>/`；`delivery_root` 与正式 run 目录都不接收尚未通过机器 QA 的文件。
4. 按目标仓库现有资产目录和命名；没有约定时使用稳定语义名，倍率写入清单或文件名。
5. 互不依赖的候选可并行导出，但每项独立执行机器 QA。任一候选失败就停止它的预览与后续处理，记录失败检查并改变来源、分组或格式策略。
6. 机器 QA 通过后才原子复制/移动到 `delivery_root` 的正式 `assets/` 并记录最终哈希；用 `asset-qa.mjs bundle` 把临时报告合为 `run_dir/qa/stage-2-asset-qa.json`，再用 `asset-qa.mjs contact-sheet` 统一生成一张联系表并逐项视觉 QA。候选名可以是连接器临时名，正式文件使用稳定语义名；交接生成器以 QA SHA-256 与正式文件 SHA-256 绑定，不要求 basename 相同，也不因纯重命名重复机器 QA。
7. 重导只替换受影响正式项。失败二进制、逐项预览和临时复合图不持久化；只有发生失败时才把尝试写入 `run_dir/diagnostics/stage-2-asset-attempts.json`，包含源节点、策略、失败检查和下一策略。

禁止导出整个 Frame 作为实现资产。section 只有在其本身就是不可拆的单一视觉作品、且用户明确接受时才可整体导出；普通落地页 section 不满足此条件。

“逐张验证”表示每项有独立结论和证据，不要求串行执行。并行只用于互不依赖的读取、导出和机器检查，不能合并或跳过门禁。

## A7 逐张资产 QA

### A7.1 机器检查

PNG 可运行：

```bash
node <skill目录>/scripts/validate-asset.mjs \
  --file <资产路径> \
  --report <QA报告路径> \
  --css-width <导出画布CSS宽> \
  --css-height <导出画布CSS高> \
  --scale <倍率> \
  --transparent <true|false> \
  --clear-edge <true|false>
```

机器检查覆盖：可解码、物理尺寸、非空内容、alpha、四角/边缘、内容 bbox、透明留白、宽高比和 SHA-256。

SVG 检查：XML 可解析、viewBox/边界正确、无确认的注入背景、mask/gradient/clipPath 未误删、内容非空、无外部失效引用，并记录哈希。

SVG 使用：

```bash
node <skill目录>/scripts/validate-asset.mjs \
  --file <候选SVG路径> \
  --report <QA报告路径> \
  --expected-view-box "<x> <y> <width> <height>" \
  --transparent <true|false> \
  --clear-edge <true|false> \
  --min-paths <最少路径数> \
  --min-gradients <最少渐变数> \
  --min-filters <最少滤镜数> \
  --min-masks <最少蒙版数> \
  --min-clips <最少裁切数>
```

`min-*` 来自源结构或首次可信导出证据；未知时传 `0`，不得猜造数量。SVG 会在隔离进程中栅格化检查真实 alpha 和边缘，不输出逐资产 PNG；合法视觉本来就贴边时传 `--clear-edge false`，但仍保留边界像素统计供视觉 QA。结构预检失败时不启动渲染。PNG/SVG 机器失败时不生成视觉预览。

逐项机器检查完成后合并正式 QA：

```bash
node <skill目录>/scripts/asset-qa.mjs bundle \
  --input <asset_id>=<临时QA报告路径> \
  --input <asset_id>=<临时QA报告路径> \
  --output <run目录>/qa/stage-2-asset-qa.json
```

manifest 中每个资产的 `qa_report` 都指向同一合并文件；逐项门禁仍按 `asset_id` 独立读取和验证，不因合并而减少检查。

### A7.2 视觉检查

所有正式项机器通过后运行：

```bash
node <skill目录>/scripts/asset-qa.mjs contact-sheet \
  --manifest <run目录>/asset-manifest.json \
  --output <run目录>/qa/stage-2-asset-contact-sheet.svg \
  --reference <run目录>/figma-reference.png
```

使用这一张联系表逐项与 Figma 最终视觉核对：

- `content_layers` 全部存在，`excluded_layers` 全部不存在；
- 方向、镜像、旋转、裁切、透明、颜色、混合、光效和层级正确；
- 边缘没有截断，安全留白足够且不过大；
- 逻辑 bbox、比例、倍率和 placement 正确；
- 普通文字/代码背景没有被误吞，资产不是整页截图或占位图。

任一项失败，`qa_status=fail`。只重导受影响资产，重新完成机器和视觉 QA；禁止改报告伪造通过或用 CSS 修白底/截断/比例。

联系表不替代逐项结论。若某项必须在父容器裁切、底色或层级中才能判断，可为该项生成一次定向复合证据；只保留实际参与放行的证据，不批量保留逐项预览。

## A8 产物与离开门禁

使用 `../rules/03-公共状态契约.md` 与 `../rules/05-第二阶段数据契约.md` 写入：

1. 更新后的 `design_analysis`、补读报告、来源/置信度、轮次和未解决风险；
2. `stage-2-handoff.json` 与 `asset-manifest.json`；
3. 每张资产的源节点、包含/排除层、格式、倍率、逻辑/视觉/导出/像素边界、安全 padding、placement、用户覆盖、哈希和 QA；
4. 最终文件与 QA 报告路径、`can_enter_stage_3` 和阻塞原因。

`stage-2-handoff.json` 的公共外壳必须把 `stage-1-handoff.json` 列为输入，把 manifest、资产和 QA 报告列为输出；回复不复制补读报告或 manifest 全文。

完成事实文件和 QA 后，用生成器写交接：

```bash
node <skill目录>/scripts/generate-stage2-handoff.mjs \
  --stage1 <stage-1-handoff.json> \
  --manifest <run目录>/asset-manifest.json \
  --reread-report <run目录>/reread-report.json \
  --timing <run目录>/timing.json \
  --reference <run目录>/figma-reference.png \
  --contact-sheet <run目录>/qa/stage-2-asset-contact-sheet.svg \
  --output <run目录>/stage-2-handoff.json

node <skill目录>/scripts/validate-handoff.mjs \
  --file <run目录>/stage-2-handoff.json
```

生成器重算 manifest/资产/QA 哈希、统计、活动产物和门禁；`workflow_state` 已在交接内，默认不另写 `state.json`，仅兼容旧消费者时追加 `--state-output <run目录>/state.json`。禁止随后手工修改派生字段。计时 scope 尚未完整结束时可先生成并校验一次，停止计时后再运行同一命令生成最终版本；第二次应为秒级确定性操作。

只有读取分数达标、无关键 blocking、用户边界落实、所有必需资产 QA 通过、manifest 与文件一致，且无正文截图化、整页切图、文字重复或背景误吞时，转换为 `stage_2_assets_ready`。

## A9 回退和禁止事项

- Frame 身份变化：回第一阶段，废弃本阶段和全部下游证据。
- 发现第一阶段分类错误：更新受影响计划后继续本阶段。
- 后续发现字段或资产错误：回本阶段只补读/重导受影响项，再顺序恢复第三、四阶段。
- 禁止生成页面、改布局或用 CSS 掩盖资产问题。
- 禁止参考截图裁片、占位图、低倍率预览、未验证文件和模糊资产。
- 禁止把未通过 QA 或哈希过期的资产交给代码阶段。


## 响应式模式补充

响应式任务只补读影响布局决策的字段：Auto Layout/约束、父子锚点、文字换行、图片裁切区、异形可伸缩区和交互遮挡关系。资产仍使用同一份正式 manifest；只有资产切分发生变化时才触发既有资产失效规则。`responsive_plan_ready` 为 false 时不得进入第三阶段。
