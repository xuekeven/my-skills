# 第一阶段：读取并规划当前画板

本阶段只读设计并输出可审计计划；不修改目标项目、不导出实现资产、不生成页面。

## P1 进入条件

- 进入本阶段时确认已用 `workflow.mjs begin --stage 1 --phase rule_loading` 一次启动阶段与首个 phase；规则读取完成后用 `transition --from-phase rule_loading --to-phase design_read` 原子切换。计时结构遵循公共状态契约 C4。
- 用户提供精确 Figma 节点链接、可读取的唯一当前选区、一张 UI 截图，或含上述设计引用的需求文档。需求模式先建立产品契约与页面映射，再对每页执行本阶段；缺失/不明确的链接进入澄清，不能猜测节点。
- 已明确目标项目时，读取其技术约定；目标项目未知时仍可分析设计，但把仓库适配标为后续待确认。
- Figma URL 与当前选区同时存在时，以用户当前消息明确指定者为准；两者不一致必须报告。

截图输入无法产生 Figma 节点 ID、组件、变量或原始资产字段，所有相应项保留并标记来源/缺失原因，不得伪造。

## P2 锁定身份与最终视觉

### P2.1 Frame 身份

1. 读取当前选择或解析精确 `node-id`。
2. 确认目标是 Frame；若选中子节点，向上识别所属 Frame，同时记录原选区与最终 Frame。
3. 固定记录文件 key、Frame ID、名称、宽、高、坐标、读取来源和验证时间。
4. 生成 `run_id` 并初始化 `workflow_state`。

文件 key、Frame ID 或宽高无法确认时标记 `blocked`。截图输入用图片哈希与宽高作为只读身份，并明确 `input_type=screenshot`。

### P2.2 最终视觉

取得目标 Frame 的完整最终视觉截图，记录导出倍率、像素尺寸和哈希。截图只作为读取、分组和验收证据，不能被页面引用为实现资产。

Figma 节点按以下低往返顺序读取：

1. 先对精确根节点调用一次 `get_design_context`。
2. 根读取成功后，在同一并行批次读取 `get_metadata`、精确最终 screenshot 和 variables。
3. 下载最终 screenshot 一次以核对尺寸和哈希；不要重复下载同一 URL。
4. 只有根响应截断、身份/section/资产边界不可确定或出现 `final_visual_conflict` 时，才在第一阶段调用子节点 `get_design_context`。

最终视觉用于发现图层数据不能直接表达的蒙版、布尔结果、裁切、隐藏效果、镜像、旋转、混合模式、半透明叠加和组件 override。结构与截图冲突时登记 `final_visual_conflict`，禁止自行任选其一。

## P3 页面分类与分段

### P3.1 画布信息

确认：设计基准尺寸、状态栏、导航栏、底部安全区、单屏/长页、滚动区域、页面背景、整体风格和默认交互状态。

固定尺寸优先。长页面必须保留 Frame 真实高度和纵向滚动；不得压缩成视口高、裁掉底部或只规划首屏。

### P3.2 页面类型

至少区分普通页面、复杂信息页、复杂活动落地页/长图营销页和海报式页面。满足下列任一类风险时进入复杂页面模式：

- Frame 明显高于单屏且由多个视觉 section 串联；
- 人物、IP、插画、复杂光效、纹理、异形卡片或大面积图文交叠；
- 多层蒙版/布尔/混合/模糊/渐变描边/内外阴影；
- 标题视觉组、艺术字、特殊字体片段或多个复杂资产组；
- 背景插图跨 section、边缘半露出或层级关系密集；
- 普通 DOM/CSS 近似会明显降低最终视觉。

复杂模式不等于整段截图化，而是按 section 拆结构、按最小完整视觉组导出资产、按分区验收。

### P3.3 Section 表

建立连续覆盖 `y=0..FrameHeight` 的 section 表。每个 section 记录：名称、`x/y/width/height`、背景、内容、图层范围、层级与交叠、文本/图片/装饰/按钮/卡片列表、资产组、还原策略、截图分区坐标和风险。

背景插图、跨区装饰和悬浮元素记录视觉归属与真实锚点，不能因跨 section 被重复实现或漏掉。

## P4 完整读取清单

响应过大时按 section 或风险子树分批读取并重组。工具截断只表示“未读全”，不表示节点不存在。

### P4.0 小 Frame 快速路径

同时满足以下条件时使用快速路径：不超过 50 个可见节点、不超过 3 个 section、非长页、根 design context 未截断、metadata 能覆盖全部节点、最终 screenshot 尺寸与身份一致、没有结构/视觉冲突。

快速路径只做根级读取和并行证据批次；复杂视觉内部字段若不影响第一阶段的主要分类、最小完整视觉组边界和 section 覆盖，直接进入 P6 队列，留到第二阶段补读。不得为了让第一阶段报告“看起来更完整”逐个读取这些子树。

### P4.1 覆盖要求

快速路径仍须覆盖全部可见节点、section、文本、主要样式、资产根、裁切/层级风险和默认交互，但只展开实现所需字段。进入复杂页面模式、用户要求深度读取、根响应截断或出现结构/视觉冲突时，完整读取 `01-深度读取清单.md` 并按其中 P4.1–P4.5 执行。

## P5 实现分类与切图计划

### P5.1 唯一主要分类

每个可见元素只归入一个主要实现类别，并记录必要例外：

- `real_text_layers`：普通标题、正文、标签、按钮文字等真实文本；
- `code_css_layers`：简单背景、规则渐变、卡片、边框、阴影、按钮、输入框、分割线、网格等；
- `svg_layers`：系统矢量图标和适合无损缩放的独立矢量；
- `png_layers`：人物、IP、位图插画、复杂合成、复杂光效和必须保持整体的视觉组；
- `ignored_layers`：最终不可见或设计辅助层，附证据。

紧凑事实把五类 ID 只写入 `design_analysis.layer_hierarchy.coverage.classified_layer_ids_by_strategy`；不再同步维护顶层分类镜像。生成器会从该索引派生覆盖计数，旧消费者明确需要时才启用兼容镜像。

同一文字不得既包含在切图里又生成代码文字。特殊字体只导出最小必要片段；普通文字和整张卡片不得因其中一个艺术字而整体切图。

### P5.2 切图分组

每个资产组列出：源图层、必须包含/排除图层、最小完整视觉语义、逻辑 bbox、视觉溢出、安全边距、格式、倍率、透明要求、落位方式、混合模式和风险。

复杂图组以“不可拆且共同形成一个视觉语义”为界；代码背景、正文、普通标题、按钮和独立可复用控件必须排除。蒙版、布尔、镜像、旋转和负缩放按最终视觉导出。

用户圈选或口头边界写入 `user_override`，优先于默认分组。例如“勋章、光芒、艺术字整体 3x PNG，勋章下方背景用代码”必须形成一个包含前三者、排除背景的资产组。

## P6 缺失字段与补读队列

### P6.1 缺失类型

缺失项使用以下错误类型之一，不能只写“读取不完整”：

- `critical_asset_bbox_missing`
- `gradient_vector_missing`
- `mask_clip_data_missing`
- `blur_effect_data_missing`
- `text_wrap_data_missing`
- `layer_order_data_uncertain`
- `background_illustration_uncertain`
- `component_override_missing`
- `special_font_strategy_uncertain`
- `final_visual_conflict`

### P6.2 定向队列

每项记录节点 ID、字段、缺失类型、为什么关键、现有来源/置信度、依赖项、最小补读节点或子树、预期证据和是否阻塞。优先补读 bbox、文本 run/折行、渐变、透明度、混合、蒙版、布尔、裁切、层级、角标锚点和变换。

只有缺失会阻止 Frame 身份、section 连续覆盖、主要实现分类或资产分组边界成立时，才在第一阶段立即补读；其他缺失只排队，不提前执行第二阶段工作。

## P7 读取完整度与预计还原度

### P7.1 读取完整度

分别评分：Frame、图层树、文本、样式、图片资产、蒙版/布尔/变换、section、图层覆盖、切图分组和风险标注，汇总 `readiness_score.overall`。

- `<90`：禁止生成，进入第二阶段补读；存在任一 `blocking_reasons` 也禁止生成。
- `90–<95`：仅当缺失均为非关键字段时可标 `generate_with_risk`；逐项记录风险。
- `>=95` 且无 blocking：可标 `normal`，进入资产阶段。

无论总分多少，Frame 未确认、最终截图未读、关键 section/资产 bbox、关键文本内容/折行、关键渐变、关键蒙版边界、关键层级或复杂页切图计划缺失时都禁止生成。

### P7.2 预计还原度

输出 `restore_fidelity.stage=estimated`：以读取完整度减去页面复杂度、字体和资产风险，给出区间、维度分解、可提升项和风险。明确写“预估、未实测”，不得冒充第四阶段还原度。

## P8 产物与离开门禁

使用 `../rules/03-公共状态契约.md` 与 `../rules/04-第一阶段数据契约.md` 写入 `stage-1-handoff.json`，公共外壳包含 `workflow_state`、`timing`、输入/输出产物，`handoff` 至少包括：

1. Frame 身份、最终视觉、页面分类、section 表和图层覆盖清单；
2. 布局、层级、文字、色彩、间距、形状、效果、资产和交互分析；
3. 真实文本/CSS/SVG/PNG/忽略分类；
4. 切图分组计划、补读队列、来源/置信度和风险；
5. 读取完整度、预计还原度、`can_enter_stage_2` 和阻塞原因。

只有 Frame/截图身份、最终视觉、完整图层/区域、关键分类、风险、补读队列和切图计划全部可审计时，转换为 `stage_1_planned`。默认使用紧凑交接并以覆盖索引证明完整性，不重复展开相同事实。先确定 `delivery_root`，运行 `scripts/workflow.mjs init --delivery-root <delivery_root> --run-id <run_id>` 创建隐藏 `run_dir`；第一阶段只向 `run_dir` 写交接 JSON、计时和只读证据，不得修改页面、目标项目代码或配置。

生成交接前用 `transition --from-phase design_read --to-phase handoff_generation` 原子切换计时。把本阶段 `handoff` 事实与 `run_id` 写入 `/tmp/figma-to-code/<run_id>/stage-1-input.json`，不要手工维护公共外壳、`workflow_state`、artifact 哈希、覆盖计数或计时摘要；运行：

```bash
node <skill目录>/scripts/generate-stage1-handoff.mjs \
  --analysis /tmp/figma-to-code/<run_id>/stage-1-input.json \
  --timing <run-dir>/timing.json \
  --reference <run-dir>/figma-reference.png \
  --output <run-dir>/stage-1-handoff.json
```

只有分析内容本身需要作为独立正式附件保留时，才传 `--details <run-dir>/stage-1-analysis-details.json>`；不得因为交接文件的体积提示临时创建该附件。生成器自动核对参考图哈希、readiness 和 blocking，并写入公共状态、输入/输出 artifact 与门禁。

生成器输出 `compact_bytes`；超过默认约 12 KB 时只输出非阻塞 warning，不影响输出、退出码、校验或阶段门禁。不得仅因该 warning 手工删改事实、拆分附件或循环重新生成。紧凑输入不写顶层五类分类数组；仅在旧消费者明确要求时传 `--legacy-classification-mirrors true`。

首次生成后运行 `../scripts/validate-handoff.mjs --file <run-dir>/stage-1-handoff.json`。该命令同时检查公共契约、漏 ID、重复分类、section 断层和身份一致性，不触发额外 Figma 读取；失败时只修紧凑事实输入。通过后用 `workflow.mjs finish --stage 1 --phase handoff_generation` 一次结束 phase 与阶段计时，再运行一次同一生成命令和校验器，固化最终计时。

## P9 禁止事项

- 禁止写页面、写样式、安装依赖、启动服务器或导出正式资产。
- 禁止只看截图猜结构，或只看图层树忽略最终视觉。
- 禁止使用上一次 Frame 数据、混用两个节点或把邻近画板当目标。
- 禁止省略无名层、低透明层、背景插图、蒙版、布尔、溢出效果和低置信度字段。
- 禁止把整页 Frame 图片列为页面实现策略。


## 响应式模式补充

仅在 `layout_mode=fixed_and_responsive` 时加载 `../rules/10-响应式适配闭环.md`。第一阶段在固定 Frame 分析之外，输出响应式计划：基准宽高、支持范围、计划 viewport、断点、超范围行为和 `responsive_component_contracts`。证据不足进入补读队列；允许端型暂为 `pending_evidence`，但第二阶段结束前必须确定或明确阻断。没有对应设计稿的宽度标记为适配验证，不计算像素还原率。
