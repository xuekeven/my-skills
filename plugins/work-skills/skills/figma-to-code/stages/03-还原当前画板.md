## I1 进入条件

- `workflow_state.status=stage_2_assets_ready` 且 `can_enter_stage_3=true`。
- 读取完整度达标，无关键 blocking，全部必需资产 QA 通过。
- 开始前再次确认文件 key、Frame ID、宽高和 manifest 身份一致。
- 已识别目标仓库框架、入口、路由、样式、资产、构建和测试约定。

只收到 `/figma-to-code implement the design` 但前置交接不可靠时，按 `../rules/02-状态机与闭环回退.md` 回退补齐；禁止凭记忆或截图直接生成。

## I2 仓库与实现基线

1. 阅读目标项目规则文件、入口和相邻页面；复用已有依赖与实现模式，不强制 React/Tailwind。
2. 检查工作区已有修改并与其共存；只改当前 Frame 所需文件。
3. 创建独立页面组件和独立路由。目标路径已存在且不属于本轮时，使用不冲突路径。
4. 把 section、图层、真实文本/CSS/SVG/PNG 分类、资产 manifest 逐项映射到实现文件，不留未归属项。
5. 为根容器提供稳定捕获标识，如 `data-figma-frame`，记录预览 URL、CSS 尺寸和默认态。
6. 先确保字体和资产加载策略可复现；字体不可得时使用最接近回退并列为可消除风险，不伪装为精确一致。

## I3 页面骨架与布局

### I3.1 根容器

- 根容器使用 Frame 的真实 CSS 宽高；设置一致的 `box-sizing`，消除浏览器默认 margin 和无关滚动条。
- 状态栏、导航栏、安全区、内容区和底部区域按设计存在性实现，不因系统常见模式自行增删。
- 单屏按真实尺寸；长页按真实 Frame 高度/内容流实现并允许纵向滚动，不能使用视口高度压缩。
- 默认固定尺寸，不擅自响应式、缩放全页、重排或改视觉比例。外围容器可居中展示，但截图根必须保持 Frame 尺寸。

### I3.2 Section 与定位

- 先按 section 建主结构，再还原组件内部。section 的 y、height、背景和交叠必须与计划一致。
- 正常内容优先使用文档流、Flex 或 Grid；只有真实叠加、装饰、角标和需要精确锚定的元素使用绝对定位。
- 绝对定位元素相对最近的语义容器定位，避免页面级坐标。跨 section 装饰明确属于哪个定位上下文。
- 精确使用读取值还原宽高、padding、margin、gap、对齐和基线；不得用 `space-between` 等不稳定分配替代固定间距。
- 核心位置/尺寸误差目标 `1–2px`，非核心装饰不超过 `3px`。

### I3.3 层级基础

建立明确 stacking context 和 z-index 表：页面底、背景渐变/纹理、背景插图、卡片、主视觉、文本、装饰、按钮/控件。`pass-through`、blend mode、opacity 或 transform 造成新上下文时必须验证隔离关系。

## I4 文字还原

### I4.1 真实文本

- 普通标题、正文、标签、按钮和输入提示使用真实文本，内容、标点、大小写、换行和文本框宽度与 Figma 一致。
- 精确设置字体族、回退、字号、字重、行高、字距、颜色、对齐和段落间距；不依赖浏览器默认值。
- 文本位置以实际基线和渲染边界核对，不只对齐 DOM 外框。
- 字体文件存在时按仓库方式加载；不存在时记录字体差异及安装/替换后的可提升量。

### I4.2 Run/span 与样式隔离

存在局部粗细、颜色、字号、斜体、描边、中英文差异或特殊字体时，按 `rich_text_run_plan` 拆 span。每个 span 只应用自己的样式；禁止在组或父节点统一加斜体/字重导致子文字污染。

区分 `font-style` 与容器的 rotation/skew。设计是容器倾斜时变换容器；设计是字形斜体时设置字体样式。

### I4.3 描边与特殊字体

- fill-only、stroke-only、fill+stroke、透明 fill+stroke、渐变 fill+stroke 必须按审计模式实现。
- 仅描边文字不能被默认文字 fill 填实；优先真实文本配 `-webkit-text-stroke`、SVG text/path 或双层文字，选择最能匹配 Figma 的方式。
- 阴影、发光和多重 effect stack 不能因做了描边而丢失。
- 只有无法稳定代码实现的局部艺术字/特殊字体片段使用已 QA 的 PNG/SVG；切图范围必须最小，普通文字仍为真实文本。
- 混合文本核对基线、行距和对齐，防止特殊字体普通化、普通文字图片化、切图模糊或重复文字。

## I5 色彩、形状与效果

### I5.1 色彩和渐变

- 使用读取的 HEX/RGBA/变量值和每层 opacity，不用“接近色”或组件库默认主题色。
- 分开实现 layer、group、fill、stroke、gradient stop、shadow 和 image opacity；禁止把 fill opacity 错施加到整层。
- 渐变必须还原类型、起止点/角度、stop 顺序/位置/透明度和延伸方式，不能只抄首尾颜色。
- 复杂渐变描边用四角、上/下/左/右中点共 8 点采样核对方向和边缘色。方向反、stop 反序或把渐变描边写成普通 border 都是错误。

### I5.2 形状和表面

- 精确还原独立圆角、边框位置/宽度、虚实线、内/外阴影、blur、backdrop blur、毛玻璃、内高光和多层效果。
- 简单卡片使用代码；异形或复杂视觉只使用计划中资产，不在代码里再近似一遍。
- 网格/噪点/纹理需匹配密度、线宽、透明度、相位和裁切；无文案背景色块只有原稿存在才实现。
- 背景插图、低透明光效和边缘半露元素即使对比度低也不能漏掉。

### I5.3 混合模式

按 `blend_mode_audit` 将 layer/fill/background 等映射到 `mix-blend-mode`、`background-blend-mode`、隔离容器或已合成 PNG。复杂合成已导成 PNG 时不得再次在 CSS 重复混合。

## I6 复杂模块与层级

### I6.1 复杂卡片混合还原

复杂卡片通常采用混合策略：卡片底/规则渐变/边框/阴影由代码实现；人物、插画、复杂艺术字和不可拆效果用局部资产；正文保持文本。必须还原：

- 卡片背景和背景插图；
- 蒙版裁切的 blur/柔光/半透明形状；
- 渐变描边、内阴影和外阴影；
- 标题、正文、特殊字体片段的真实层级；
- 装饰越界和父容器 clip 行为。

禁止把整张卡片切成图，也禁止只写一个普通渐变圆角盒子近似复杂表面。

### I6.2 微元素

虚线、分割线、手写线、标题强调线以文字/按钮/卡片为锚点，记录并实现相对 x/y/offset。标题线按文字基线与真实文字宽度定位，不能按页面绝对坐标猜。

### I6.3 角标

文字角标、按钮角标、Tab 指示、小三角、通知点相对锚定对象定位；默认位于其上层。会随文字/按钮宽度变化的角标使用相对容器，不允许页面级绝对定位。误差超过 `2px` 视为失败。

### I6.4 按钮和图标

按钮按容器、底、边框、阴影、图标和文字拆分。系统 play/arrow/check 等用真实 SVG 或稳定 CSS shape，复杂视觉图标按 manifest 使用 PNG。核对图标类型、尺寸、与文字 gap、垂直居中和视觉重心；不能用 emoji 或不匹配字符代替。

## I7 正式资产

- 只引用 manifest 中 QA 通过且哈希一致的正式文件。
- 用 manifest 的 placement、逻辑 bbox 和安全 padding 放置；显示尺寸等于设计 CSS 尺寸，保留宽高比。
- 不用拉伸、错误 `object-fit`、二次裁图或 CSS 圆角掩盖边界问题。
- 人物、标题视觉组、卡片、装饰和背景保持真实 z-index；资产画布透明留白要在定位中补偿。
- 不再次截图、抠图或临时生成替代物。白底、截断、模糊、方向、分组、比例或倍率错误立即回第二阶段。

## I8 需求驱动行为与默认态

### I8.1 有需求：实现本期行为，不止静态演示

有需求文档、页面流程或业务状态要求时，先读 `../rules/09-需求驱动交互闭环.md`。按产品契约统一实现导航参数、共享数据、状态变化与动态计算，再按各页面设计恢复默认视觉。不为静态 diff 简化或放弃明确要求的交互。

`interaction_inventory` 应引用 requirement ID，标明 implement/noop/out_of_scope/clarify、触发条件、预期状态和用例 ID。明确 noop 保留外观且无副作用，不能补 toast。未确认主流程保持阻塞；mock 与真实 API 接入状态必须区分，不自行推测接口。

### I8.2 没有需求：不猜业务

只给设计时按默认态还原，记录能确认的控件与交互；仅实现用户或设计明确说明的行为。不凭外观为所有按钮增加 toast、modal 或假提交，不猜跨页面业务。需要更深交互时说明缺少的行为定义。

### I8.3 视觉与功能分开验证

截图使用可复现的 fixture、时钟、路由和默认状态；功能用例验证真实 DOM 操作后的结果及数据一致性，不仅验证截图。只有测试环境注入固定时钟，真实运行继续动态计算。切换页面/卸载组件后清理订阅与计时器。

## I9 检查、产物与门禁

### I9.1 实现自查

按 section 核对：

- 可见元素、背景插图、内容完整性和 z-index；
- 坐标、尺寸、间距、对齐、长页高度和滚动；
- 文字内容、换行、字体、run、描边、倾斜和基线；
- 颜色、渐变方向、8 点边缘、圆角、边框、阴影、blur、透明和混合；
- 蒙版、布尔、镜像、旋转、角标、微元素和嵌套效果；
- 资产内容、透明、比例、倍率、放置及文本不重复；
- 默认状态与范围内交互同时正确，明确无操作项没有意外副作用。

仓库已有静态检查互不依赖时并行运行 lint、类型检查、测试和构建；记录实际命令、退出码、结果，不存在的检查写“不适用”及依据。浏览器运行证据只做一次：

1. 先执行 `SKILL.md` 的服务启动门禁：复用身份可确认的已有服务；纯静态页面使用绝对 `file://` URL；没有可用服务且页面不能静态运行时标记 `preview_service_not_running` 并暂停，不自行启动服务。
2. 实现与默认态稳定后运行 `scripts/shoot-preview.mjs --help`，再以正式 URL、捕获根和 Frame 尺寸执行一次；输出规范 `stage-3-preview.png` 与 `stage-3-capture-report.json`。
3. 由同一捕获报告核对根唯一性/尺寸、字体与图片加载、非空截图、运行异常、`console.error`、资源 4xx/加载失败；不要再为这些项目逐项启动 Playwright CLI。
4. 需求模式必须用项目浏览器测试或有状态浏览器会话验证跨页流程和 DOM 交互，保留实际断言与证据；单元测试不能替代页面连接验证。可合并会话减少重复，结束时恢复截图默认态。
5. 页面代码或默认态未变化时，第四阶段只读复用该截图和捕获报告；发生变化则按失效规则重拍为 `stage-4-preview.png` 与 `stage-4-capture-report.json`，不得覆盖第三阶段证据。

### I9.2 交接

按 `../rules/03-公共状态契约.md` 与 `../rules/06-第三阶段数据契约.md` 准备紧凑实现输入：预览 URL、路由、可唯一查询的捕获根 CSS selector、CSS 尺寸、修改文件、资产 ID、文本/CSS/PNG/SVG 映射、项目检查、交互和风险。临时输入放 `/tmp/figma-to-code/<run_id>/stage-3-input.json`，不进入正式 run 目录。

先运行 `scripts/generate-stage3-handoff.mjs --help`，再传入 Stage 1/2、manifest、紧凑实现输入、`stage-3-capture-report.json`、`timing.json`、`--delivery-root <delivery_root>` 和 `run_dir` 内的正式输出路径。实现输入的 `changed_files` 可相对 `delivery_root`；生成器会定位文件并规范为相对 `run_dir` 的路径，同时负责文件/资产哈希、图层全集、运行证据、状态转换、计时和 `can_enter_stage_4`。禁止手工重复维护公共外壳。生成后运行 `scripts/validate-handoff.mjs` 独立复核；停止阶段计时后再运行一次生成器和校验器以固化最终计时。

只有独立页面可访问、全部可见 section 已实现、资产一致、默认态稳定、适用代码/构建/运行检查通过且可取得精确截图时，转换为 `stage_3_implemented`。本阶段只能给生成后的暂定测量，不得宣布最终验收完成。

若唯一缺口是未运行的必需预览服务，保留已完成的实现与静态检查，停止计时并等待用户主动启动授权；不得用旧截图、错误页或跳过浏览器检查生成 `can_enter_stage_4=true`。

## I10 回退和禁止事项

- Frame 身份变化回第一阶段；字段或资产错误回第二阶段；布局/文字/CSS/组件/路由错误留在第三阶段局部修。
- 本轮修正破坏已通过区域时，只撤销当前执行者本轮修改并缩小范围，不覆盖用户改动。
- 禁止整个 Frame、大段 section、正文、普通标题或按钮文字截图化。
- 禁止占位图、模糊低倍率图、伪造图层/文案/交互和无证据近似。
- 禁止整页重构、覆盖旧页面、修改无关区域、删除用户改动、提交或推送 Git。
- 禁止跳过项目检查直接进入第四阶段。

## 需求模式补充门禁

每个 implement/noop 都映射到代码与功能用例；多页面共用统一数据源。子页交接仅表示本页阶段完成，全部页面就绪后才验证跨页流程。功能结果按产品契约记录；未运行或失败不得伪装通过。


## 响应式模式补充

先完成原始尺寸固定稿并通过基准门禁，再创建独立响应式入口。响应式可共享数据、交互和已通过 QA 的资产，但不能静默改写固定稿基准。实现摘要需提供 `responsive_validation`：`layout_mode`、计划/已捕获 viewport、基准宽度回归、根缩放/溢出/裁切检查和实现就绪状态；最终 `can_deliver` 由第四阶段生成。第三阶段只验证响应式实现证据是否就绪；最终响应式未通过由 Stage 4 适配门禁阻断，不提前消耗最终验收。
