# 产品契约与证据格式 v1

本扩展不改变四阶段 `schema_version=1`。单 Frame 继续使用原生成器；需求模式另增产品聚合文件。所有以下文件引用（含功能结果内部引用）都相对 `product-contract.json` 所在目录；允许绝对源文档路径。路径应指向授权读取的文件，SHA-256 由实际文件计算。

## 提取与规划

```sh
python3 <skill>/scripts/extract-requirements.py --help
python3 <skill>/scripts/extract-requirements.py --input <需求.docx> --output <product_dir>/requirements-extracted.json
node <skill>/scripts/validate-product.mjs --help
node <skill>/scripts/validate-product.mjs --contract <product_dir>/product-contract.json
```

提取器只读取 DOCX，不联网或执行文档内容。`blocks` 覆盖正文/表格段落，`tables` 保留行列，`urls` 合并显式 URL 和超链接目标。`#pN` 是 OOXML 中从 1 开始的段落序号，不是页码。图像、批注、修订、域等需按 `warnings` 补读；不保证从图像或断在 URL 中间的多段文字自动恢复链接。

`product-contract.json` 必需字段：

| 字段 | 内容 |
|---|---|
| `schema_version`, `product_id` | `1`，稳定产品运行标识 |
| `data_mode` | `mock` / `api` / `local`，只描述本次实现 |
| `sources[]` | `{id,path,sha256}`，原文档/用户澄清记录；不要只引用二次总结 |
| `screens[]` | `{id,route,run_dir,default_state,design}`，设计为 `{kind:"figma",file_key,node_id}` 或 `{kind:"screenshot",reference:{path,sha256}}` |
| `requirements[]` | `{id,screen_ids,disposition,behavior,evidence}`；evidence 为 `[{source_id,location,text}]` |
| `cases[]` | `{id,requirement_ids,level,given,when,then}`，level 为 `unit/component/browser` |
| `questions[]` | `{id,description,blocking,status,resolution?}`，status 为 `open/resolved` |

按需要补充 `data_model`、`state_model`、`transitions`、`api_contract`、`time_policy`、`assumptions` 与 `implementation_plan`；不强制一套业务 schema。导航和 noop 在 `behavior` 或 transitions 中写清来源页、控件、输入、目标、状态变化/不变化；对应浏览器用例不能只校验文本存在。

示例记录（不是可以原样用于生产的完整契约）：

```json
{
  "id": "R-start-lesson",
  "screen_ids": ["plan", "lesson"],
  "disposition": "implement",
  "behavior": "点击某课程开始学习，按该 lessonId 进入课程页并展示同一课程的学科及起止时间。",
  "evidence": [{"source_id":"prd","location":"word/document.xml#p9","text":"图一点击‘开始学习’，进入图二课程学习页。"}]
}
```

文档原话、语义拆解与实现假设分开；示例位置应由真实提取结果替换，不把示例段号当证据。每个 implement/noop 至少一个用例。`clarify` 可存在于规划，但会阻止最终交付；解决后更新 disposition 并记录依据。

## 功能结果

`functional-results.json`：

```json
{
  "schema_version": 1,
  "product_id": "<与契约相同>",
  "contract_sha256": "<当前契约文件真实哈希>",
  "environment": "<预览地址、浏览器/测试框架、数据模式、时区、fixture 与时钟设置>",
  "executed_at": "<实际执行的 ISO 时间>",
  "implementation_files": [{"path":"<所有实现与测试/fixture/配置文件>","sha256":"<真实哈希>"}],
  "cases": [{
    "id": "C-start-lesson",
    "status": "pass",
    "level": "browser",
    "method": "automated",
    "command": "<实际执行命令>",
    "exit_code": 0,
    "actual": "<观察到的路由、课程参数、目标内容及断言结果>",
    "evidence": [{"path":"<测试报告/trace/截图>","sha256":"<真实哈希>"}]
  }]
}
```

- 结果需精确覆盖契约的全部 cases，不能重复 ID 或删除失败用例。
- `status` 为 `pass/fail/blocked/not_run`；后三者均阻断交付。
- `method=manual` 时提供 `steps` 字符串数组和证据，不能用“人工通过”替代真实步骤；自动用例必须有实际命令和零退出码。
- `implementation_files` 包含每页 Stage 3 的 changed_files，以及影响行为的测试、fixture、共享状态、路由、配置等文件。不允许测试旧版本后只更新哈希冒充新测试。
- 动态截图固定时钟和数据，功能测试单独推进时钟。没有非默认态设计稿时验证行为与可用性，不声称该态通过像素级还原。

## 聚合验收

```sh
node <skill>/scripts/validate-product.mjs \
  --contract <product_dir>/product-contract.json \
  --results <product_dir>/functional-results.json \
  --output <product_dir>/product-acceptance.json
```

脚本先检查来源、契约、测试覆盖、结果与文件哈希，再逐页运行原 `validate-handoff.mjs` 校验四阶段证据，核对设计身份与实现文件覆盖，汇总视觉和功能门禁。任何失败退出码非零，并尽可能输出 `can_deliver=false`。每轮使用新的 output 文件名（例如 `product-acceptance-2.json`），保留历史；最终回复引用最新一轮，不复用旧成功报告。

结构合法不等于需求正确，日志存在也不等于实际断言有效。执行者仍负责核对完整原文、真正运行测试与审查可观察结果。最终报告同时给出数据模式、各页视觉结论、功能覆盖和剩余问题；不能用视觉分数抵消业务失败。

## 最终 UI UX 报告

需求模式在产品聚合验收后必须生成 `ui-ux-report.md`，它是给人阅读的最终交付报告，不替代 JSON 交接和机器门禁：

```sh
node <skill>/scripts/generate-ui-ux-report.mjs \
  --contract <product_dir>/product-contract.json \
  --results <product_dir>/functional-results.json \
  --acceptance <product_dir>/product-acceptance.json \
  --output <delivery_root>/ui-ux-report.md
```

报告必须包含：

- 交付目录、需求来源、产品契约、功能结果、聚合验收文件；
- 所有页面的路由、设计稿身份、默认状态、视觉门禁、截图和 Stage 3/4 交接；
- 已实现、明确无操作、本期不做和待确认的需求范围；
- 核心流程、参数传递、共享数据和动态行为；
- 全部功能用例的类型、结果、实际观察和证据；
- 每页截图验收、还原度、修改文件、视觉风险；
- 阻塞项、剩余风险、mock/API 状态、最终是否可交付；
- 报告输入文件的 SHA-256 和可复现生成命令。

报告必须如实反映失败、未执行、缺失证据和 `can_deliver=false`，不能用“已完成”标题掩盖风险，也不能把截图路径或测试日志当作没有实际断言的通过证明。若需求模式未使用产品契约，不生成伪造的产品报告；单 Frame 任务仍使用原有阶段交接，可按用户要求生成单页报告但应明确“非产品聚合报告”。
